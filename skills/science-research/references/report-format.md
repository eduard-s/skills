# Deliverable contract

Produce three linked artifacts when files can be created. Use local/download links the host supports; never invent a file path or claim a file exists before writing it. In chat-only environments, use the same three clearly separated sections, with anchors if supported or ordinary section names if not. Do not call an anchor a separately saved report.

## Scientific brief — `evidence-summary.md`

Default: 250–450 words, excluding deeper-reading links. Shorter suits a narrow question; the user can request more detail.

Suggested shape, using natural headings in the user's language:

**Answer:** Practical conclusion in two sentences, including its important uncertainty.

**What research shows:** Two to four short findings with citations near claims. Explain useful effects in everyday terms. State population/system, comparison and time frame when they affect meaning. Label indirect evidence and inference.

**What this means for you:** Bounded, evidence-supported implications. State the relevant limit or health next step without generic boilerplate.

**Confidence:** An informal label and one sentence explaining it. Different findings may need different labels.

**Read more:** Two to five direct links if that many useful sources exist, each labeled with what the reader will find. Cite fewer when evidence is sparse; never invent sources to meet a range.

End with links to **Detailed research notes** and **Separate personal-experience report** (unless the user opted out). Include the actual search date, material assumptions, and a compact scope limit. Keep forum experiences, vote totals, and forum-derived recommendations out of this brief.

## Personal experiences — `anecdotal-report.md`

Follow [anecdotes.md](anecdotes.md), including an honest access/no-cases result. If the user opts out, no separate empty artifact is needed.

## Detailed research notes — `research-notes.md`

Put the audit trail here:

- Question, assumptions, search date, tools and actual queries, filters, coverage/stopping reason, and access limits.
- Policy version and any explicit user-approved additions/restrictions for this run.
- Scientific source records and claim map from [search-and-appraisal.md](search-and-appraisal.md).
- Material excluded/unavailable sources with reasons; proposed policy additions distinct from evidence actually used.
- Disagreements, overlapping study populations/reviews, gaps, and evidence that could change the answer.
- A separate anecdote-search log with queries, dates/access, deduplication, and links to included cases.

Reflect work actually done. A reproducible search trail does not promise identical results from another engine or on another date.

## Final check

Read the brief alone: can a non-specialist understand the conclusion and limit? Verify:

- Each central scientific claim has eligible source support; confidence comes only from scientific evidence.
- Numbers preserve units, denominator, comparison, and time frame; missing baseline data are not invented.
- Included URLs were opened, checked after redirects, and classified correctly. User-supplied text not independently opened is explicitly marked as supplied/unverified.
- Full-text/abstract/summary access and integrity-check limits are honest.
- Anecdotes come from readable accounts or state why none were verified.
- Report links point to existing artifacts or actual chat sections.

Without browsing, supplied extracts can support a bounded assessment of their text. Do not claim independent URL, publication-status, or recency verification; make missing checks visible in confidence and scope.
